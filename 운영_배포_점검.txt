융합서비스디자인 챗봇: 피드백 반영 및 운영 점검
기준일: 2026-11-03

1. 정확한 정보

- 학교 공지, ERICA 블로그, 총학생회 채널을 질문 종류에 따라 구분한다.
- 질문의 핵심 단어를 검색어에 남기고, 관계없는 교육원·단과대 자료가 답변에 섞이지 않도록 검증한다.
- 본문을 읽지 못한 검색 링크는 AI의 사실 근거로 사용하지 않는다.
- 게시일이 확인된 자료는 화면에 날짜를 표시한다. 게시일이 없는 자료를 최신 공지로 단정하지 않는다.
- 예비군, 장학금 마감, 교통 운행처럼 바뀔 수 있는 내용은 원문 공지와 학기를 확인한다.

2. 클릭과 입력 줄이기

- 소속을 선택하지 않아도 질문할 수 있다. 학과별 정보가 필요할 때만 소속을 선택한다.
- 자주 묻는 장소·행정 질문은 확인된 내용을 답변에 바로 보여준다.
- 출처 카드에는 제목, 요약, 확인 가능한 경우 게시일을 보여준다.
- 장학명이 모호하면 사이트를 여러 번 찾아보라고 하기보다 대화에서 정확한 장학명을 묻는다.
- 목표: 일반적인 질문은 답변 화면에서 해결하고, 원문 확인이 필요할 때만 출처를 한 번 연다.

3. 현재 남아 있는 제한

- 블로그 RSS는 최근 글 위주이며, 검색 결과 페이지의 형식이 바뀌면 과거 글을 못 찾을 수 있다.
- 총학생회 Linktree와 인스타그램의 게시물 본문을 항상 자동으로 읽을 수 있는 것은 아니다.
- 학기별 날짜, 자격, 금액을 자동으로 최신 상태로 보장하는 관리 체계는 아직 없다.
- PC의 로컬 Qwen 모델은 답변 생성에 수십 초가 걸릴 수 있고, 동시 사용자가 늘면 더 느려질 수 있다.

4. 실제 공개 배포 전 필요한 것

- 항상 켜져 있는 서버에서 웹 앱, Ollama, Qwen 모델을 실행하고 HTTPS 주소를 마련한다. 정적 웹 호스팅만으로는 현재 챗봇이 작동하지 않는다.
- 현재 앱은 시작 시 DATABASE_URL을 요구한다. 공개 환경에는 PostgreSQL 연결을 준비하거나, ERICA 챗봇만 독립 실행하도록 기존 SQL 기능과 분리해야 한다.
- 비밀번호와 API 키는 배포 환경의 비밀 설정에 넣는다. 예시 파일의 이전 값이 실제 사용 중이었다면 해당 값을 교체한다.
- 자주 묻는 질문별로 담당자, 원문 주소, 게시일, 마지막 확인일을 기록하고 정기적으로 재확인한다.
- 검색 실패율, 잘못된 출처 비율, 답변 시간, 원문 클릭 수를 기록해 개선한다.
- 공개 전 학생 질문 목록으로 답변 정확도와 모바일 화면을 시험하고, 여러 명이 동시에 사용할 때의 속도를 확인한다.
- 공용 컴퓨터에서 사용할 경우 브라우저에 남는 대화 기록을 사용자가 쉽게 지울 수 있게 안내하거나 보관 정책을 정한다.

5. 현재 확인한 상태

- 타입 검사와 배포용 빌드는 로컬에서 통과했다.
- 운영 모드로 웹 화면과 질문 API가 실행되는 것을 확인했다.
- 공개 인터넷 배포와 다중 사용자 성능 검사는 아직 진행하지 않았다.
